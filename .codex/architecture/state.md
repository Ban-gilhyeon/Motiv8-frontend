# 상태와 데이터 흐름

## 상태 분리

- 서버 상태: 운동 목록, 기록, 통계, 사용자 정보
- 인증 상태: 토큰, 사용자 세션, 복원 중 여부
- UI 상태: 모달, 선택 날짜, 폼 입력, 탭
- URL 상태: 필터, 페이지, 날짜 범위

서버 상태를 전역 UI 상태에 복사하지 않는다. 캐시·재조회·무효화 전략을 먼저 정한다.

## 요청 흐름

1. 화면이 query 조건을 결정한다.
2. feature API가 공통 client를 호출한다.
3. 응답을 화면 모델로 변환한다.
4. 로딩·성공·빈 상태·오류를 렌더링한다.
5. 변경 성공 후 관련 데이터를 재조회한다.

## 동시성

- 중복 제출 방지
- 오래된 응답의 덮어쓰기 방지
- refresh 요청 단일화
- 화면 이탈 시 취소 또는 결과 무시
